Isolated .NET SDK

Install and manage exact .NET SDK versions in your own directory—without changing the system-wide installation or PATH.

View source code ↗Read documentation ↗
How it helps

One machine. Multiple SDK versions. No global changes.

Keep SDK experiments isolated, choose exact versions deliberately, and verify the results before use.

✓ Exact-version installation
✓ User-owned SDK directory
✓ Audit and verification
✓ System PATH unchanged
01 /

The problem

Different projects may require particular .NET SDK versions. Installing them globally changes the development environment for everything else running on the machine.

Evaluating new releases and reproducing version-specific issues should not require modifying a working system-wide setup.

02 /

The solution

Keep selected SDK versions in a user-owned directory, outside normal global installation paths. Install exact versions, inspect the inventory, audit servicing status, verify installations, and remove versions you no longer need.

Deliberate isolationSDKs remain outside the system installation and PATH.
Verifiable versionsUse precise SDK versions and check what was installed.
Cross-platform interfacesPowerShell on Windows; Bash on Linux and macOS.
03 /

How it works

SDK installation is staged, checked against expected version and checksum information, and promoted into the isolated inventory. Listing, auditing, verifying, and removal are separate operations.

04 /

Design decisions

Filesystem isolation is not a security sandbox. The SDK still operates with the user's permissions; explicit invocation keeps the active SDK choice clear.
